### Mobile-first interactions

The gallery supports explicitly visible prev/next buttons, numbered controls, arrow keys and native horizontal **touch swipes**. The canvas responds to taps with a high-contrast traveling ring, a DOM ripple, and the original point-field disturbance. Touch-action is `pan-y` so ordinary vertical scrolling remains available. A full-screen mobile menu uses regular links and does not depend on hover. `prefers-reduced-motion` disables moving artwork and simplifies transitions.

### Technical choices

Native Web Animations API, requestAnimationFrame, passive touch/pointer listeners, IntersectionObserver, and modest inline SVG illustrations keep the single-file preview self-contained. Animations do not need any third-party CDN or network access. The portfolio is generated by `uv`-managed Python (Jinja2, markdown-it, BeautifulSoup) into HTML/CSS/JS, then served by any static host.

## Verification boundaries

Browser regression checks execute the exact generated HTML via injected content and verify the functional state changes with Chromium touch input. This environment blocks automated navigation to `file://` and `localhost` routes, and Android in-app file viewers may prohibit scripts. Consequently, **mobile runtime on a physical phone using a normal HTTPS link has not yet been validated**. To verify it, serve `dist/` over HTTP or deploy, then repeat swipe, menu, and canvas tests on the phone. Avoid claiming that a locally extracted HTML file behaves identically in every Android viewer.
